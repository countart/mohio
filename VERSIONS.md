| 4.8.2 | 2026-08-08 | 2030-08-08 | AGPL-3.0-or-later | v4.8.2 | Patch release, security and data-integrity focused. `modify ... where` with a two-part condition now filters to the matching rows instead of silently changing every row. A mixed `and`/`or` condition is now a check-time error rather than being silently grouped, matching the browser-side rule. Release hygiene: the version is defined in one place with a guard preventing the two version files from disagreeing, the incorrect license label is removed from every shipped file, the project-wide license reference now points at the real `LICENSE` file, login and safety libraries ship in a plain install, and the source distribution is published alongside the wheel. | 4.9.0 | 2026-08-22 | 2030-08-22 | AGPL-3.0-or-later | v4.9.0 | Feature and correctness release. **Breaking:** `on.failure` now means an operation ERRORED, not that it found nothing. A query that matches no rows is a normal, empty result and runs the ordinary path, so code that used `on.failure` to mean not-found must move to `when ... is empty` or `otherwise`. A block whose `when`/`otherwise` branch does more work, including another database call or a `give back`, now runs that branch as a full execution context instead of reporting an empty database error. Saving into a table that has no `id` column works: a table whose identity is a combination of columns, such as a session and a flag name, no longer refuses every write. `save or update` no longer requires a unique constraint the table may not have, so it works on the tables the compiler itself creates, and it stops silently inserting duplicates on MySQL. The MySQL backend can create and inspect tables again, which had failed on every write. The database seeder creates each table with the constraint its real identity requires, and re-running it no longer duplicates rows. A comparison between two values now runs its own result handlers, and reading an undeclared name in one fails loud instead of answering false. Audit records for a data change now identify which row changed and state how that row is identified; on tables whose identity is entirely sensitive the record says plainly that row-level identification is still pending. That audit identity currently covers Postgres and SQLite; on MySQL and MongoDB the record reports its identity as unknown. `/ping` and `/health` now report the build commit alongside the version, so a deployment can be identified exactly. File scope for this version is fixed by the `LICENSE-SCOPE.md` committed at the tag above. |
| 5.0.0 | 2026-09-08 | 2030-09-08 | AGPL-3.0-or-later | v5.0.0 | Major release. The data layer was rebuilt on a recovered model: a source is described once and referenced through the connection, so `db.table.column` resolves against a semantic index rather than a per-shape binding, and the same one contract reads five real database engines (PostgreSQL, MongoDB, MySQL, MariaDB, SQLite) with no per-engine code. **Classification is now value-bound:** a field tagged `[phi]`, `[pci]`, or `[pii]` keeps its protection wherever its value goes, so copying a protected value into a variable, holding it, joining it into a sentence, or passing it through a task no longer strips the protection; masking follows the value and hides only the protected portion of a string, and a copied protected value seals on the write into any column, not only its declared one. A control that refuses or reverses now leaves an auditable trace: a purpose-limitation refusal, a compensated saga, and a right-to-erasure refused under a legal hold each write a record where before they left only an error on screen, so what a control prevented is provable and not only what it allowed. Uploaded files are handled end to end: stored durably to local or S3-compatible object storage and so surviving a redeploy, tagged content encrypted at rest, served only through a handler that checks who is asking and refuses and audits anyone who is not, and every file operation records whether the content was protected. A privacy tag survives translation to a deploy language rather than being silently rewritten. The AI-governance prompt boundary for `ai.decide` and `ai.agent` was tested against a real model for the first time and held against every injection family. Roughly 250 commits. File scope for this version is fixed by the `LICENSE-SCOPE.md` committed at the tag above. |

| 5.1.0 | 2026-09-16 | 2030-09-16 | AGPL-3.0-or-later | v5.1.0 | Feature release, and the one that made the language buildable by somebody who did not write it. This release began with a single Windows install failure; running that down surfaced the packaging, verification, and diagnostics gaps that this release closes. A newcomer persona went from finishing one task in fifteen to ten in ten, which is the measure this release was actually steered by. **Compliance:** a governed write now carries its audit through to the trail it claims, closing the gap where a record could be reported as written and not be there; sector governance was verified FIRING rather than merely declared, with the confidence floors, the encrypted classification and the compile-time refusal each demonstrated end to end on a real request. **Data:** money is exact decimal on all four engines across eighteen currencies, keeping its currency through arithmetic and through a round trip to storage, and refusing to add two different ones; a shape that names its table now governs what is written to it. **The language:** a route may carry a value in its address (`{{id}}`) and bind it, where before it matched nothing and answered every real request as not found; `flow`, `walk` and `map` are spellable, demonstrated and documented, with the two map spellings that were never built now refused by name; and a view can finally say one of these per record, with `{{ each row in rows }}`, ending the workaround of binding the first three rows by hand. **Files:** a browser can be handed a temporary signed link and upload straight to the configured bucket, so the bytes never pass through the application. **Correctness:** a whole class of silent conflation is closed. Where two forms differed only by a word the parser discards, they arrived identical and the meaning was lost; five real instances were found by sweeping every rule in the grammar, including one that signed permission to READ for a program asking to WRITE, and one dormant instance where a test assertion and its negation were the same assertion. **Getting started:** `mio new` and `mio init` scaffold the same clean starter the installer writes, so a `pip install` no longer leaves a pioneer to clone this repository and inherit its own demo deploy, which pointed at a billed AI switch. **Throughput:** measured on PostgreSQL, roughly seven to nine thousand governed transactions a minute with every audit record kept. File scope for this version is fixed by the `LICENSE-SCOPE.md` committed at the tag above. |
| 6.0.0 | 2026-10-19 | 2030-10-19 | AGPL-3.0-or-later | v6.0.0 | Major release: it carries breaking changes, listed in `Docs/manual/mohio-manual-upgrading-to-6.0.0.md`. **Security:** since 4.9.0 a lookup that finds no row is not a failure, so a refusal written in its `on.failure` (for example `give back [403]` when a care relationship or an approval is missing) never ran, and the handler went on into the protected read, the write or the commit; this was present in 4.9.0 through 5.1.0 and is now refused at check and at run, showing the `when <name> is empty` form that refuses. A refusal inside a transaction, or an answer from a branch inside it, now rolls the transaction back. Every match clause was always AND-ed on every engine. A [phi], [pci] or [pii] value bound for an outside AI or service call is refused at check, with a run-time backstop, unless it is masked or the record is sent `stripped`. **Breaking:** a handler opened with `new` is refused, showing the `listen for` form it becomes (`mio fmt --write` converts it); a connection whose variable is unset refuses unless its line names a `default` or the run gives `--db`; a not-found refusal in `on.failure` refuses at check. **Numbers:** every number is born exact: a literal, a form or query value, a JSON body, an AI or connector response and a database read all enter as exact decimals and stay exact, so 0.1 plus 0.2 is 0.3, a sum of cents is a sum of cents, and outgoing JSON writes exact numbers; `round.to` rounds ties half away from zero, `round.up` and `round.down` go away from and toward zero, and an over-precise money amount on a write is rounded with a warning outside a regulated sector and refused under one. **Data:** declared types are real database column types on SQLite, Postgres, MySQL and Oracle, a bare decimal reads back identically on all four, booleans read back as booleans everywhere, and `mio migrate typed-storage` converts an older table with a dry run that lists every value that will not convert; time zones are declared by name, stored in UTC and shown with `in.timezone`; native joins run chained, side by side, on retrieve and on Mongo, with `with.all` returning matched and unmatched rows as two lists; filters, ordering, paging and projection push down to the database, and every part that still runs in Mohio is reported; `paginate by request.page default 1` works as ruled. **Protection:** a PHI or PCI value stays masked after it is copied, joined or passed to a task, including in a page and in `as.json`; webhook replay protection no longer needs a time window; uploads are durable on the platform's configured bucket with nothing to declare, and an ephemeral host with no store refuses rather than losing the file. **AI:** the journey cost ceiling covers every operation that calls a provider, and a failure says which provider, which stage and which error. **The language and its checks:** MioScript gained reset, alert, confirm, copy, media, timers, strict validation and share, and a clicked row carries its record key; `text.long` holds unlimited text; `check against` closes like every check; the five state operators act only on held values; `mio check` now refuses a read of a name declared nowhere in a handler, never mistakes text in a string for retired syntax, and suggests only verbs that work; a mioconnect timeout is the real timeout on every call. **Links and sessions:** a one-time link (`mioauth.token.create`, `verify token`, `mioauth.token.revoke`) works once, for one purpose, for a while, with only its hash stored, on all five engines; a form's guard token belongs to the session it was issued to, and the home page now sends the session cookie it never sent. **Files:** `copy` is built through the file area and its zone rules; the file area is never served to the web, which it was; on the platform store a path under `public/` goes to the public bucket with a plain address and everything else to the private bucket, read only by a signed link, never for an underscore-prefixed name. **Data:** a `dec.N` field truncates an over-precise write on every engine and verb, and SQLite keeps a scale too wide for an integer as exact text; `round.up N` and `round.down N` take places; `connect ... default "app.db"` falls back only when written, and says so; a timespan ending `until now` filters; `member not.found` and `where name not.empty` work; the in-list filter `where status active, pending` works, where it had never worked. **Safety:** owed audit records drain on their own; `mio check` warns when a handler can refuse after a write no transaction covers; a temporary disk refuses a SQLite file and a local file write; every `on.failure` can read `failure`, and an AI failure says which provider, stage and error on every AI operation; refusals that only happened at run now happen at check, including a line that read as two conditions and did nothing. **Landed after the first 6.0.0 draft (2026-10-08):** **Field binding:** a protected value is now sealed bound to its table, column and row `id`, so a valid ciphertext copied into another row, column or table refuses as `encryption.wrong_place` instead of reading back there as that row's value; values written by earlier releases still open unchanged, and their re-seal is planned for 6.0.1. A protected field on a table with no `id` column refuses in this release (`protected_field_needs_id_key`); composite-keyed tables are planned for 6.0.1. **Audit relay:** `mio audit relay` never reports a caught-up trail while a record is still owed: it counts each owed record with its reason and exits non-zero, and every `mio audit` message masks the database password. **Decimal scale:** a value compared with a declared `dec.N` field is placed at that field's scale, in Mohio, so the same comparison answers the same on every engine. **Egress:** one egress gate decides what may leave at every outbound boundary, including everything the map machinery prints, and a field is masked by its own table's classification, never by a same-named field of another table.
