| 4.8.1 | 2026-08-05 | 2030-08-05 | AGPL-3.0-or-later | v4.8.1 | Patch release. Fixes a packaging gap where the installed wheel shipped with no grammar file at all (`mohio.lark`, the sector profiles, and the langmaps relocated into `mohio_data/` so they are actually included); `connect db as sqlite from env.X` now consults its declared source instead of silently falling back to the constructor default; `miosearch`'s check-time severity corrected from WARNING to ERROR to match its real runtime crash. Also includes the durable session-store provider seam (in-memory and Postgres-backed session storage, survives a process restart, preserves role and hold-scoped state), which landed on `main` between `v4.8` and this tag and lives inside `mohio_interpreter.py`, already part of the Licensed Work. File scope for this version is fixed by the `LICENSE-SCOPE.md` committed at the tag above. |
| 4.8.2 | 2026-08-08 | 2030-08-08 | AGPL-3.0-or-later | v4.8.2 | Patch release, security and data-integrity focused. `modify ... where` with a two-part condition now filters to the matching rows instead of silently changing every row. An app that declares no database no longer crash-loops when the host sets a `DATABASE_URL`, and `mio audit verify` now opens Postgres and MySQL rather than only local files. A page with no address set now answers only at the home path instead of at every URL, closing an unauthenticated-write surface (both the ordinary and the crafted-request routes). A failed step inside a `transaction` now rolls the whole block back instead of leaving a partial write committed. A misspelled or unknown field access now fails loud with a suggestion instead of silently returning nothing, and `random.token`/`random.number` used without their required details refuse clearly rather than yielding nothing. Searching a plain in-memory list with `find`/`retrieve`/`grab` now gives a clear message instead of failing silently (full support for querying held sources is tracked separately). A mixed `and`/`or` condition is now a check-time error rather than being silently grouped, matching the browser-side rule. Release hygiene: the version is defined in one place with a guard preventing the two version files from disagreeing, the incorrect license label is removed from every shipped file, the project-wide license reference now points at the real `LICENSE` file, login and safety libraries ship in a plain install, and the source distribution is published alongside the wheel. File scope for this version is fixed by the `LICENSE-SCOPE.md` committed at the tag above. |
| 4.9.0 | 2026-08-22 | 2030-08-22 | AGPL-3.0-or-later | v4.9.0 | Feature and correctness release. **Breaking:** `on.failure` now means an operation ERRORED, not that it found nothing. A query that matches no rows is a normal, empty result and runs the ordinary path, so code that used `on.failure` to mean not-found must move to `when ... is empty` or `otherwise`. A block whose `when`/`otherwise` branch does more work, including another database call or a `give back`, now runs that branch as a full execution context instead of reporting an empty database error. Saving into a table that has no `id` column works: a table whose identity is a combination of columns, such as a session and a flag name, no longer refuses every write. `save or update` no longer requires a unique constraint the table may not have, so it works on the tables the compiler itself creates, and it stops silently inserting duplicates on MySQL. The MySQL backend can create and inspect tables again, which had failed on every write. The database seeder creates each table with the constraint its real identity requires, and re-running it no longer duplicates rows. A comparison between two values now runs its own result handlers, and reading an undeclared name in one fails loud instead of answering false. Audit records for a data change now identify which row changed and state how that row is identified; on tables whose identity is entirely sensitive the record says plainly that row-level identification is still pending. That audit identity currently covers Postgres and SQLite; on MySQL and MongoDB the record reports its identity as unknown. `/ping` and `/health` now report the build commit alongside the version, so a deployment can be identified exactly. File scope for this version is fixed by the `LICENSE-SCOPE.md` committed at the tag above. |
